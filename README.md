# 🕯️ 심야 테이블 (Midnight Table)

2D 공간에서 내 캐릭터를 직접 움직여 테이블에 모여 앉고, 실제로 사람들과 보드게임을 하는 느낌을 주는 실시간 멀티플레이 웹 플랫폼입니다. 현재 탑재된 게임 모듈은 **머더미스터리**이고, 테스트 시나리오 **「해무관의 마지막 잔」**(2인, 약 75분)이 들어 있습니다.

## 바로 실행하기

필요한 것: **Node.js 20.11 이상**

```bash
npm install
npm run build
npm start
```

- 게임: http://localhost:3000
- 운영자 시나리오 에디터: http://localhost:3000/admin (기본 비밀번호 `midnight-admin`, 환경변수 `ADMIN_PASSWORD`로 변경)
- 한 컴퓨터에서 여러 명을 흉내 내려면 창마다 `http://localhost:3000/?profile=2`처럼 `profile` 값을 다르게 주세요. (같은 브라우저는 세션 토큰을 공유하므로, 같은 주소로 두 탭을 열면 먼저 연 탭이 끊깁니다)

개발 모드(핫 리로드): `npm run dev` → http://localhost:5173

### 다른 사람과 인터넷/LAN으로 플레이할 때

브라우저는 **https 또는 localhost 주소에서만 마이크를 허용**합니다. 텍스트 채팅은 어떤 주소에서도 되지만, 음성까지 쓰려면 다음 중 하나가 필요합니다.

- TLS 인증서 지정: `SSL_KEY_FILE=key.pem SSL_CERT_FILE=cert.pem npm start`
- 또는 https 리버스 프록시/터널(Cloudflare Tunnel, ngrok 등) 뒤에서 실행

서로 다른 네트워크(NAT) 사이의 음성이 연결되지 않으면 TURN 서버를 지정하세요.
`ICE_SERVERS='[{"urls":"turn:turn.example.com:3478","username":"u","credential":"p"}]'`

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | 3000 | 서버 포트 |
| `ADMIN_PASSWORD` | midnight-admin | 운영자 에디터 비밀번호 |
| `RECONNECT_GRACE_MS` | 120000 | 연결이 끊긴 참가자를 기다리는 시간 |
| `DATA_DIR` | ./data | 시나리오·업로드·방 상태 저장 폴더 |
| `ICE_SERVERS` | Google STUN | WebRTC STUN/TURN 목록(JSON) |

## 플레이 흐름

1. 닉네임과 아바타(머리·머리색·피부·옷·옷색·소품)를 정하고 입장합니다. 회원가입은 없습니다.
2. 라운지 게시판에서 방 제목/번호를 보고 들어갑니다. 🔒 방은 비밀번호를 묻습니다. 방 번호로 바로 입장할 수도 있습니다.
3. 저택 살롱을 걸어 다니다(WASD/방향키/클릭) 중앙 테이블 의자에 앉으면(`E` 또는 의자 클릭) 게임 상자를 고를 수 있습니다. 앉은 사람 모두가 준비하고 인원이 맞으면 4초 뒤 자동으로 시작합니다. 인원이 모자라면 몇 명이 더 필요한지 표시됩니다.
4. 테이블 위의 인물 카드를 집어 배역을 정합니다.
5. 진행 흐름에 따라 봉투가 도착합니다. 봉인을 끌어올려 뜯고, 카드를 뒤집어 설정집·공용집·단서를 확인합니다. 설정집은 책처럼 모서리를 끌어 넘기고, 단서는 확대·돋보기로 봅니다.
6. 토론·심문 단계에서는 밀담 구역(서재·온실·응접실·회랑)에 함께 들어가 둘만 대화하거나, 능력 카드를 위로 끌어 테이블에 내려놓아 사용합니다.
7. 최종 투표에서 지목 도장을 용의자 카드에 찍고 길게 눌러 확정하면, 표 집계 → 진범 공개 → 결과 → 사건의 진상·인물별 결말이 펼쳐집니다.

### 로비 레이어와 게임 모듈의 분리

로비 레이어(`server/src/platform`, `client/src/ui`, `client/src/world`)는 **방·이동·구역·채팅·음성·테이블(게임 고르기)** 만 압니다. 설정집·공용집·투표 같은 단어는 전부 `modules/murder-mystery` 안에만 있습니다. 모듈은 `GameHost`를 통해 로비에 딱 네 가지만 요청합니다: 상태 갱신 알림, 일회성 연출 이벤트, 구역 목록/격리 on·off, 이름표 라벨. 로비는 모듈이 보낸 뷰를 그대로 전달할 뿐 내용을 해석하지 않습니다.

**새 장르 추가 방법**
1. `server/src/modules/<장르>/`에 `GameModuleDefinition`을 구현하고 `server/src/index.ts`에서 `modules.set(...)`으로 등록
2. `client/src/modules/<장르>/`에 UI 컴포넌트를 만들고 `client/src/modules/registry.ts`에 등록

로비·테이블·방 목록·재접속은 수정할 필요가 없습니다.

### 서버 권위

- 이동: 클라이언트는 즉시 예측해 움직이고, 서버는 속도(토큰 버킷)·벽 통과·구역 정원을 검증해 어긋나면 되돌립니다(`m:fix`).
- 정보: 비공개 자료는 서버가 **공개 대상 ∩ 열람 권한**으로 계산해 해당 플레이어의 뷰에만 넣습니다. 클라이언트에는 받을 자격이 있는 데이터만 도착합니다.
- 구역 격리: 채팅은 서버가 수신자를 계산하고, 음성은 서버가 “같은 채널”인 사람끼리만 WebRTC 시그널을 중계합니다. 채널이 달라지면 양쪽 클라이언트가 연결을 끊습니다.
- 모든 게임 동작(카드 사용, 투표, 확인, 연장)은 서버가 규칙을 검사한 뒤 반영합니다.

### 재접속 정책

- 브라우저 `localStorage`에 세션 토큰이 저장됩니다. 새로고침·일시적 끊김 후 같은 토큰으로 돌아오면 **같은 캐릭터, 열람한 자료, 카드 잔여 횟수, 위치, 받았던 채팅 기록**이 그대로 복원됩니다. (비밀번호 방도 다시 묻지 않음)
- 연결이 끊기면 다른 참가자 화면에 “연결 끊김 · 남은 시간”이 표시되고, **유예 시간(기본 2분)** 동안 “전원 확인” 조건은 그 사람을 기다립니다. 타이머는 계속 흐릅니다.
- 유예 시간이 지나면 **부재 처리**됩니다: 확인은 자동 통과, 투표는 기권, 캐스팅 중이면 남은 배역이 자동 배정됩니다. 게임은 계속되고, 부재자는 방이 살아 있는 한 언제든 돌아와 그대로 이어서 플레이할 수 있습니다.
- 대기 중인 방에서 유예 시간이 지나면 퇴장 처리됩니다. 아무도 접속하지 않은 방은 대기 10분/진행 60분 뒤 정리됩니다.
- 방·게임 상태는 3초마다 디스크에 저장되어 **서버를 재시작해도** 복원됩니다(타이머는 다운타임만큼 보정).

## 시나리오 에디터 요약

`/admin`에서 코드 수정 없이 다음을 편집하고 저장합니다. 저장과 동시에 서버와 같은 규칙으로 검증되며, 오류가 없고 “공개”인 시나리오만 게임 선반에 올라갑니다.

- 기본 정보(제목, 소개, 표지, 최소/최대 인원, 플레이 시간, 투표 공개 방식)
- 캐릭터(공개 소개, 필수 여부, 투표 참여 여부, 설정집 페이지, 능력/아이템 카드)
- NPC 용의자(플레이어가 맡지 않는 투표 후보)
- 공용집(서술/대사/소제목 블록, 대사의 화자 라벨)
- 단서(텍스트/이미지 업로드, 공용/개인과 열람 캐릭터)
- 진행 흐름(공개 이벤트와 토론·심문·투표 페이즈를 끌어서 배치, 대상·내용·제한시간·진행 조건·밀담 가능 여부, 항목별 실제 수신자 미리보기)
- 밀담 구역(맵 위에서 끌어 만들기·이동·크기 조절, 구역별 최대 인원)
- 엔딩(판정할 투표, 진범, 성공/실패 결과, 사건의 진상, 인물별 결말)

설정집·단서 본문 마크업: `# 제목`, `## 소제목`, `> 인용`, `- 목록`, `!! 비밀 강조`, `**굵게**`

GM(규칙 설명 역할)은 별도 기능이 아니라 설정집에 진행 설명을 쓴 일반 캐릭터로 만들면 됩니다. 피해자처럼 투표하지 않는 역할은 “투표 참여”를 끄세요.

## 검증 (Linux/macOS)

```bash
npm test
```

Playwright(Chromium, 가짜 마이크)로 실제 브라우저 여러 개를 띄워 다음을 확인합니다.

- `tests/unit-mm.test.ts` 규칙: 공개/익명 투표, 동률 실패, 투표 불참 캐릭터, 공개 대상×열람 권한 교집합(누설 방지), 타이머 연장 쿨타임과 자동 진행
- `tests/smoke-server.mjs` 방 생성~엔딩 전체 흐름(비밀번호, 순간이동 차단, 중복 배역, 관전자 조작 거부, 카드, 개인 단서 격리)
- `tests/smoke-reconnect.mjs` 끊김 → 유예 대기 → 부재 처리 후 진행 → 같은 토큰으로 복귀(캐릭터·열람·카드·위치·채팅 기록), 게임 중 관전 입장, 2인실 정원 초과 차단
- `tests/smoke-restart.mjs` 게임 도중 서버 재시작 후 복원
- `tests/play-2p.mjs` 두 브라우저로 UI를 직접 조작해 방 생성부터 엔딩까지 (봉투 뜯기 드래그, 책장 넘기기, 단서 확대/돋보기, 카드 끌어 사용, 도장 드래그와 길게 눌러 확정, 새로고침 복원 포함)
- `tests/zones-3p.mjs` 같은 방 3명: 2명은 서재 안, 1명은 홀. 텍스트·말풍선이 서로 새지 않는지, **WebRTC 음성 연결이 같은 구역끼리만 생기고 실제 오디오 바이트가 흐르는지**, 구역을 나오면 연결 대상이 바뀌는지
- `tests/editor.mjs` 운영자 인증, 새 3인 시나리오 작성·이미지 업로드·구역 생성·저장 후 즉시 게임 선반 반영

## 사용한 라이브러리와 이유

- **Socket.IO** — WebSocket 위의 자동 재연결, ack(요청/응답), room 브로드캐스트. 서버 권위 구조와 재접속 복원을 적은 코드로 안정적으로 구현.
- **Preact + @preact/signals** — 오버레이 UI가 많은 게임 HUD를 가벼운 번들(gzip 약 60KB)로 구성.
- **Vite** — 게임/에디터 두 페이지 번들링과 개발 중 핫 리로드.
- **zod** — 시나리오 스키마를 서버와 에디터가 공유해 같은 규칙으로 검증.
- **Express + multer** — 정적 파일, 운영자 API, 이미지 업로드.
- **tsx** — TypeScript 서버를 별도 컴파일 없이 실행.
- **Galmuri / Pretendard / 나눔명조** (OFL) — 도트 UI, 본문, 문서용 한글 글꼴.
- 그래픽과 사운드는 외부 에셋 없이 코드로 생성(Canvas 도트, WebAudio 합성, SVG 단서 이미지).
